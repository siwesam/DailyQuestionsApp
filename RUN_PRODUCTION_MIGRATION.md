# Running Database Migration on Render Production

## Quick Fix for "Failed to load quote" Error

The error occurs because your production database doesn't have the new AI quote fields yet. Here's how to fix it:

## Option 1: Run Migration via Render Shell (Recommended)

### Step 1: Access Render Shell
1. Go to https://dashboard.render.com
2. Click on your **backend web service**
3. Click on the **"Shell"** tab in the top navigation
4. Wait for the shell to connect

### Step 2: Run the Migration
In the Render shell, run:
```bash
python backend/migrations/add_ai_quote_fields.py
```

You should see output like:
```
Starting migration: Adding AI-related fields to quotes table...
Detected PostgreSQL database
Adding 'source' column...
✓ Added 'source' column
Adding 'is_ai_generated' column...
✓ Added 'is_ai_generated' column
Adding 'ai_relevance_reason' column...
✓ Added 'ai_relevance_reason' column
Updating existing quotes...
✓ Updated existing quotes
Migration completed successfully!
```

### Step 3: Verify
1. Go back to your deployed app
2. Try to get a quote again
3. It should work now!

## Option 2: Run Migration Locally Against Production DB

If you prefer to run it from your local machine:

### Step 1: Get Your Production Database URL
1. Go to Render Dashboard
2. Click on your PostgreSQL database
3. Copy the **External Database URL**

### Step 2: Set Environment Variable Temporarily
```bash
export DATABASE_URL="your-production-database-url-here"
```

### Step 3: Run Migration
```bash
cd backend
python migrations/add_ai_quote_fields.py
```

### Step 4: Unset the Variable (Important!)
```bash
unset DATABASE_URL
```

## Option 3: Add Migration to Startup (Automatic)

To make migrations run automatically on every deploy:

### Step 1: Create a startup script
Create `backend/startup.sh`:
```bash
#!/bin/bash
echo "Running database migrations..."
python migrations/add_ai_quote_fields.py
echo "Starting application..."
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

### Step 2: Make it executable
```bash
chmod +x backend/startup.sh
```

### Step 3: Update Render Start Command
In your Render service settings:
- Go to **Settings** → **Build & Deploy**
- Change **Start Command** to: `./startup.sh`
- Click **Save Changes**

## Troubleshooting

### Error: "column already exists"
This is fine! It means the migration was already partially run. The script handles this gracefully.

### Error: "connection refused"
- Check that your DATABASE_URL is correct
- Verify your database is running on Render
- Check that your IP is allowed (Render databases are usually open)

### Error: "permission denied"
- Make sure you're using the correct database credentials
- The database user needs ALTER TABLE permissions

### Still getting "Failed to load quote"?
1. Check Render logs for specific errors
2. Verify OPENAI_API_KEY is set correctly
3. Make sure your database has some quotes (run init_db.py if needed)

## Verify Migration Success

You can verify the migration worked by checking the database:

### Via Render Shell:
```bash
python -c "
from app.database import engine
from sqlalchemy import text
with engine.connect() as conn:
    result = conn.execute(text('SELECT column_name FROM information_schema.columns WHERE table_name=\\'quotes\\''))
    print([row[0] for row in result])
"
```

You should see: `['id', 'quote_text', 'author', 'category', 'keywords', 'created_at', 'source', 'is_ai_generated', 'ai_relevance_reason']`

## What This Migration Does

The migration adds three new columns to the `quotes` table:
- `source` (VARCHAR): Where the quote came from (e.g., 'manual', 'brainyquote', 'ai_generated')
- `is_ai_generated` (INTEGER/BOOLEAN): Whether the quote was generated by AI
- `ai_relevance_reason` (TEXT): AI's explanation of why this quote matches the user

These fields enable the AI quote matching system to work properly.
